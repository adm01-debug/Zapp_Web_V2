## Parte 2 — concurrent safety: o achado real

**O `StrictMode` nunca esteve montado.** O `main.tsx` renderizava `<App />` direto no `createRoot`.

Isso importa porque o repo **já tinha defesas escritas para o StrictMode** — que, sem ele, nunca eram exercitadas:

| Arquivo | Defesa |
|---|---|
| `src/hooks/realtime/useSupabaseRealtime.ts:94` | *"Grace period absorbs React StrictMode/remount churn…"* |
| `src/components/calls/VoIPPanel.tsx:71` | *"(o StrictMode monta duas vezes) e o cleanup NÃO solta a liderança"* |
| `src/components/team-chat/__tests__/*` | comentários sobre duplicação por double-render |

Código defensivo contra um mecanismo que não está ligado é código **não verificado**. Em React 19 o `StrictMode` monta/desmonta/remonta cada efeito e re-renderiza duas vezes em **desenvolvimento** — é o detector padrão de efeito sem cleanup e impureza de render.

**Ligado em `src/main.tsx`** (somente afeta dev; em produção o React o ignora).

### Prova de que os hooks resistem

`src/hooks/__tests__/realtimeStrictMode.test.tsx` — 3 testes montando `useSupabaseRealtime` **dentro de `<React.StrictMode>`**:

| Caso | Verificação |
|---|---|
| canal compartilhado | `supabase.channel` chamado **1×**, não 2 (StrictMode monta 2×) |
| ciclo completo de remount | nenhuma saída em `console.error` (é onde o React reporta efeito quebrado) |
| flag `enabled=false` | nenhum canal aberto, mesmo sob StrictMode |

**Prova por mutação** (o teste só vale se falhar quando o código quebra):

| Mutação | Resultado |
|---|---|
| desligar o compartilhamento de canal (`entry` sempre `undefined`) | **2 testes falham** ✅ |
| ignorar o flag `enabled` | **1 teste falha** ✅ |
| código original | 3/3 passam |

O hook **passa** — o compartilhamento de canal com grace period funciona de fato. O valor desta etapa não é corrigir um bug: é **provar que não há** ali, e deixar o detector ligado para pegar os próximos.

## Escopo do que foi revisado (honestidade)

O repo tem **421 arquivos de hooks custom** e **489 arquivos de teste**. Não revisei os 421 um a um — isso não é varredura, é reescrita, e não caberia num PR. O que ficou:

- **varredura mecânica** das APIs removidas/deprecadas: **completa** (tabela acima), resultado zero em produção;
