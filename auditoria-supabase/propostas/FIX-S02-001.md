# FIX-S02-001: 63 migrations com NULL statements no ledger

## Problema
63 versions entre 20261006234158 e 20261026210000 possuem `statements = NULL`
no ledger `supabase_migrations.schema_migrations`.
O arquivo SQL existe no repo mas o SQL aplicado nao esta registrado.
Viola regra 7 do CLAUDE.md. Replay do schema impossivel para esses objetos.

## Correcao

NAO APLICAR EM PRODUCAO SEM APROVACAO DO JOAQUIM

Para cada migration com NULL statements, o procedimento e:

1. Confirmar o estado real do objeto ao vivo ANTES de escrever:
```sql
-- Para funcoes:
SELECT pg_get_functiondef(oid) FROM pg_proc WHERE proname = 'nome_da_funcao';
-- Para indices:
SELECT indexdef FROM pg_indexes WHERE indexname = 'nome_do_indice';
-- Para tabelas:
SELECT column_name, data_type FROM information_schema.columns WHERE table_name = 'nome_da_tabela';
```

2. Usar o helper para gerar o SQL de registro (nao transcrever manualmente):
```bash
node scripts/db-audit/register-migration.mjs supabase/migrations/<version>_<name>.sql
```

3. O helper gera:
```sql
UPDATE supabase_migrations.schema_migrations
SET statements = ARRAY[
  '<statement 1>',
  '<statement 2>'
]
WHERE version = '<version>'
  AND statements IS NULL
RETURNING version, name;
-- Deve retornar 1 row; se retornar 0, a version nao e NULL ou nao existe
```

4. Repetir para todas as 63 versions.

Periodo concentrado: 2026-10-06 a 2026-10-26 (migrations recentes)

## Verificacao final
```sql
SELECT COUNT(*) FROM supabase_migrations.schema_migrations WHERE statements IS NULL;
-- Deve retornar 0
```

## Rollback
Nao aplicavel — o UPDATE apenas preenche dados ausentes, nao altera o schema do banco.
Se um UPDATE errado for aplicado, usar:
```sql
UPDATE supabase_migrations.schema_migrations SET statements = NULL WHERE version = '<version>';
```

## Risco de Regressao: ALTO
Cada UPDATE deve confirmar o estado real do objeto ANTES de escrever.
Nao copiar o SQL do arquivo sem verificar se e identico ao que foi aplicado.
Dois casos historicos de problema com este processo (CLAUDE.md secao auditoria 2026-09-25).
