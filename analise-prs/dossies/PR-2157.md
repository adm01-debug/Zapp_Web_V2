## Critério 1 — Válida?

**NÃO.** A Dependency Review Action é uma verificação útil para qualquer projeto com `package.json`, mas este PR **apaga dois workflows existentes** (`eslint.yml` e `static.yml`) que fazem parte do CI oficial do repositório. Isso tornaria a PR inválida mesmo sem a regra de bloqueio de workflows. Evidência: `git diff --stat` mostra 95 deleções em dois arquivos que existem na `main` (`ls .github/workflows/` confirma ausência — esses dois já foram removidos da main como "alien workflows"; mas se ainda não estivessem, apagá-los seria regressão).

**Nota:** Na `main` atual (`5a4632c`) já não existem `eslint.yml` nem `static.yml` (confirmado via `ls .github/workflows/`), então as deleções no diff são artefato de branch criado antes da remoção desses arquivos.

O arquivo adicionado (`dependency-review.yml`) é novo e não afeta código existente. Portanto sem nova regressão em código, mas a PR demonstra descuido: inclui deleção de arquivos CI que eram parte do sistema.
