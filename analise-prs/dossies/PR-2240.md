- Params: `segq`, `segorigem`, `segstatus`, `segproprietario`, `segpagina`, `segporpagina`

## 2. As 4 perguntas com evidência (diff lido)

### 2.1 Ainda válida?
**SIM** — sem persistência em URL, filtros são perdidos ao navegar para um segmento e voltar. Diff confirma a adição de `parseSegmentLibraryFilters()` que lê os `searchParams` e os hidrata no estado do hook.

### 2.2 Traz regressão?
**NÃO**:
- Filtros padrão em `DEFAULT_SEGMENT_LIBRARY_FILTERS` são os mesmos do estado anterior (tudo limpo/vazio); a URL sem params reproduz o comportamento original
- `SEGMENT_LIBRARY_OWNER_NONE = 'sem-proprietario'` é valor reservado novo — não colide com IDs de usuário reais (UUIDs)
- `userId` adicionado ao retorno do hook não remove nenhum campo existente
- `localStorage` para page size: com `try/catch` implícito via wrappers — page size volta ao default se localStorage falhar

### 2.3 Já implementada em main?
**NÃO** — `parseSegmentLibraryFilters`, `syncSegmentLibraryUrl`, `segmentLibraryPageSizeKey` e o arquivo de teste são novos no diff.

### 2.4 Regra de negócio correta?
**SIM** — URL como fonte de verdade para filtros é o padrão correto para SPAs; permite bookmark e compartilhamento de contexto. Page size por usuário em localStorage é preferência local legítima (não precisa persistir no servidor). O filtro `sem-proprietario` é necessário para encontrar segmentos sem dono atribuído.
