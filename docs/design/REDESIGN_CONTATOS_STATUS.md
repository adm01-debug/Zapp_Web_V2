- **Etapa 40 — `is_lid_legacy` não é filtrado por nenhuma das duas RPCs**: `grep -rn "is_lid_legacy" supabase/migrations/*.sql` só retorna a migration que criou a coluna (`20260906000001_e31_contacts_is_lid_legacy.sql`); nem `search_contacts` nem `contacts_count_by_type` a referenciam. Decisão: `useContactsKpi` também não filtra (`filterLidLegacy=false` no call site de `ContactStatsCards`), para que `deltaTotalPct`/`empresasDistinct`/etc. sejam calculados sobre a mesma população que gera `contactCountByType['all']` (usado nas tabs e no card Total) — evita a KPI Total divergir do badge "Todos".
- **Etapa 41/45 — `deltaTotalPct` explode para um número absurdo com o dataset real desta base**: verificado via REST direto (`/workspace/qa/verify-data.mjs`, login com o usuário QA, `Prefer: count=exact`) que **as 1.516 linhas de `contacts` têm `created_at` dentro dos últimos 30 dias** (mais antiga: `2026-08-27`, "hoje" é `2026-09-07`) e **zero linhas** na janela de 30-60 dias atrás. A fórmula do Apêndice C (`pct(total, max(total-novos30,1))`) usa `total-novos30` como proxy do "total há 30 dias"; com quase toda a base recente esse denominador vira `max(0,1)=1`, e o resultado é uma porcentagem de dezenas de milhares (`+99900%` renderizado). Confirmado que **não é bug de implementação** — é a fórmula especificada no plano se comportando exatamente como escrita, só que essa base real (aparentemente criada/migrada em bloco em `2026-08-27`, sem histórico anterior) é um caso degenerado para essa fórmula. Não alterei a fórmula por conta própria (não estava autorizado a redesenhar a métrica); mantive fiel ao Apêndice C e registro aqui para decisão de produto — a mesma degenerescência devia acontecer com `deltaNovosPct` sempre que `novosPrev30=0` e `novos30>0` (vira sempre exatamente +100%, que é o comportamento visto no card "Novos (30 dias)").
- **Etapa 33 — não existe "view de notificações" no código real**: `grep -rn "notification" src/pages/ViewRouter.tsx` não retorna nada; `VIEW_MAP` do `ViewRouter.tsx` não tem entrada `notifications`, só existe uma aba "Notificações" dentro de `SettingsView.tsx` (`Tabs defaultValue="schedule"`, não controlado, sem deep-link por query param). Além disso `ContactsView` é montado por `ViewRouter` sem nenhuma prop (`<ViewComponent />` em `VIEW_MAP`, linha ~127), então não há `onNavigateTo` disponível dentro da árvore de Contatos sem tocar `ViewRouter`/`Index.tsx` — proibido pela seção 3.3 do plano. Decisão (regra 15): o sino de `ContactsTopActions.tsx` dispara `document.dispatchEvent(new CustomEvent('open-command-palette'))`, mecanismo real já existente e escutado por `GlobalKeyboardProvider.tsx` (mesmo Cmd+K), de onde o usuário navega para Configurações. Não é uma central de notificações dedicada — é o mecanismo real mais próximo sem inventar componente novo nem tocar arquivo proibido. Registrado como pendência honesta.
